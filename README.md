# 临时邮箱（Cloudflare Workers）

自己域名上的临时收件箱：随便编个前缀就能收信，网页看验证码和原文，程序用四个接口取码。只收不发，跑在 Cloudflare 免费套餐上。

参考实现是 [maillab/cloud-mail](https://github.com/maillab/cloud-mail)（核查版本 `a792cdc`）。本仓库只保留"任意前缀收信 + 查询 + 取码 + 删除 + 到期清理"，其余能力全部删除，不是隐藏页面。

## 能做什么

- 任意前缀收信，不需要预先创建邮箱
- 网页输入前缀查询，验证码单独高亮、一键复制，可看 HTML 原文和正文图片
- 程序用访问密钥调用接口：状态、列表、详情、删除
- 邮件从收到起保留 24 小时，到期自动清理；也可以验证成功后立刻删除
- 内嵌图片随邮件存取，删信或过期后图片地址立即失效

## 不做什么

- 不发信、不转发、不回复
- 不做附件下载（只处理正文里的内嵌图片）
- 不做账号、注册、多用户、角色权限、管理后台、统计
- 不识别图片里的验证码
- 不提供已读状态、回收站

## 怎么部署

看 [docs/DEPLOY.md](docs/DEPLOY.md)。需要：GitHub 账号、Cloudflare 账号、一个已接入 Cloudflare 的域名。全程免费套餐。

接口怎么调看 [docs/API.md](docs/API.md)。每个取舍的理由和验证状态看 [docs/DECISIONS.md](docs/DECISIONS.md)。

## 目录

```
src/
  index.js     入口：fetch / email / scheduled 三个 handler
  api.js       四个接口 + 图片读取
  inbound.js   收件：解析 MIME、存正文、存内嵌图片
  extract.js   验证码提取（纯规则，不用模型）
  html.js      HTML 清洗、转文本、cid 图片改写
  db.js        D1 建表与查询，建表幂等
  config.js    配置解析与硬限制
public/
  index.html   单页界面，无构建步骤
test/
  inbox.test.js 用真实 MIME 跑通收件到删除
```

## 本地开发

```bash
npm install
npm run dev          # http://127.0.0.1:8787
npm test             # 19 项测试，真实 D1 + 真实 MIME
```

本地开发用 `.dev.vars`（已在 `.gitignore` 里）：

```
ACCESS_KEY=自己随便写
MAIL_DOMAIN=example.com
```

`wrangler dev` 不能接真实邮件，收件链路由测试覆盖；真实投递只能在部署后验收。

## 免费额度边界

| 项目 | 免费额度 | 本项目的用法 |
| --- | --- | --- |
| Workers 请求 | 10 万/天 | 网页轮询 5 秒一次，一次等待约 36 次请求 |
| Workers CPU | 10ms/请求 | 超过 1 MiB 的邮件不解析，直接留占位记录 |
| Workers 子请求 | 50/请求 | 收件 2-3 次 D1 调用，列表 1 次 |
| D1 存储 | 500MB/库 | 24 小时自动清理，单库 500MB 是硬上限 |
| D1 行大小 | 2MB | 单张内嵌图片上限 256KB，一封最多 8 张 |
| Email Routing | 25MiB/封 | 超过 1 MiB 的信只记录"收到但没存" |

## 已知限制

- **1 MiB 以上的邮件不保存正文**。免费套餐每次请求只有 10ms CPU，解析几 MB 的 MIME 会触发 `EXCEEDED_CPU`。这类邮件会留一条 `too_large` 记录，网页显示"超出大小限制"，不会假装没收到。
- **验证码是规则提取**，不是模型识别。取不到时返回空字符串并保留整封邮件，需要人工看原文。被拆成 `123 456` 的码、图片里的码、引用历史邮件里的旧码都可能取不到或取错。
- **同一封邮件重复投递会产生两条记录**。不做去重，因为平台不承诺投递语义。
- **没有速率限制**。访问密钥是唯一凭据，泄露就等于邮箱被读；发现泄露请在控制台换掉 `ACCESS_KEY`。
- **没有未读/已读**。读多少次都不改变邮件状态。

## 与参考实现的差异

| 参考实现 | 这里 | 原因 |
| --- | --- | --- |
| 收信前必须有 account 记录，靠开关放行任意收件人 | 删掉 account，直接按信封收件人存 | 本项目不预建邮箱，也不需要用户体系 |
| 验证码走 Workers AI（`llama-3.1-8b-instruct-fast`） | 纯规则 | 免费额度每天 1 万 Neurons，模型有延迟和抖动，失败静默返回空码；规则零成本、结果可解释 |
| 图片存 R2 / S3 / KV 三选一 | 存 D1 的独立图片表 | 不需要额外服务、不需要绑支付方式；2MB 单行上限远高于单张内嵌图，500MB 库容量靠 24 小时清理兜住 |
| 邮件列表按 id 分页、无本次范围 | 按地址 + `since` / `after` / `before` 查 | 覆盖"本次发码范围"和"继续查新来信" |
| Vue 前端 + 构建产物 | 单文件 HTML，无构建 | 部署只要导入仓库，不需要 build 命令 |
| GitHub Actions 自动部署（要账号级 API Token） | 只用 Workers 的 Git 集成 | 不需要在仓库里放 API Token，也不再把初始化密钥拼进 URL |
| `/api/init/{secret}` 初始化 + 注册管理员 | 首次请求自动建表 | 少一步手工操作，也少一个会进日志的密钥 |
